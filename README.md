# Receipts — наши рецепты и что есть дома

Веб-приложение (PWA) на двоих: коллекция рецептов, позже — сток продуктов.
База и вход — Supabase, хостинг — GitHub Pages.

## Структура
- `supabase/schema.sql` — таблицы и права доступа. Выполняется один раз.
- `supabase/add_member.sql` — добавить человека в дом.
- `import/` — инструменты разбора: `common.py`, `to_sql.py` (JSON → SQL), `media_sql.py` (фото). Сами партии рецептов в репозиторий не кладутся — SQL с рецептами передаётся отдельно.

## Правила карточек
- Название ингредиента начинается с категории: «сыр тильзитер», а не «тильзитер».
- Категория для поиска и стока (`base`) — внутреннее поле, в карточке не показывается.
- Взаимозаменяемые ингредиенты — одна строка через «или» (`alt_group`).
- Оригинальная формулировка — в `raw`, пересчёт ложек в граммы — в `grams` с пометкой ≈.

## Разделы и скрытие
- `category` — раздел меню (Завтраки, Супы, Салаты, Горячее, Закуски и бутерброды, Выпечка, Десерты, Соусы и намазки, Напитки). Меняется в карточке.
- `hidden` — «не для меня»: рецепт не показывается в общем списке, но им можно поделиться. Скрытые видны в фильтре «Скрытые», там же их можно удалить совсем.

## Загрузка партий рецептов
1. `supabase/migrations/*.sql` — изменения схемы, по порядку, один раз.
2. SQL с рецептами (передаётся отдельно, не из репозитория). Повторный запуск обновляет текст, но сохраняет статус, оценку, заметки и ссылку для мамы.
3. `supabase/seed_media_batchNN.sql` — привязка фото (сами фото лежат в `docs/media`).
